## 一、执行摘要

FundLens 是一款面向个人投资者的 **Windows 本地资产快照分析工具**：将支付宝、同花顺与手动录入的持仓统一汇总，展示总资产、资产结构、浮动盈亏与历史快照变化。项目采取“Flutter 界面层 + 纯 Dart 领域层 + Python 数据引擎 + 加密本地存储”的四层架构，边界清晰、原则性强。

总体评价：

- **架构质量高**：界面层不直接计算金融指标、不直接访问数据库或 Python；领域层不依赖 Flutter、数据库与网络；Python 引擎只做 OCR、名称匹配与行情获取，职责划分严格且有文档化契约约束。
- **测试覆盖充分**：560 个 Dart 测试、87 个 Python 测试；2026-08-03 全量回归门禁全绿（dart test 19 通过、flutter test 539 通过、pytest 86 通过、analyze/ruff/mypy 无问题、15 步端到端回归 6/6 通过、性能预算达标）。
- **安全与隐私设计成熟**：数据不出本机、SQLCipher 加密数据库、Argon2id + AES-256-GCM 备份、日志脱敏、引擎子进程隔离，均有对应自动化测试。
- **主要短板在工程化**：无 CI 流水线、Dart lockfile 未按约定提交、单文件过大（`import_review_controller.dart` 约 1500 行）、脚手架残留（领域包 README 仍为 TODO 样板）、数据库尚无迁移机制。

项目处于 **V1 已完成开发、发布验收未完全闭环**的状态：发布安装包已产出（`dist/installer/FundLens-Setup.exe`，约 275 MB），但仓库内尚无“干净 VM 安装/升级/卸载”验收的完成记录。

## 三、技术架构

### 3.1 分层结构

```
Flutter Windows 界面层（Riverpod 应用编排）
        │  Ports：HoldingRepository / SnapshotRepository / DataEngineClient
        ▼
纯 Dart 领域层 packages/fundlens_core      内置 Python 数据引擎 engine/
（分类/估值/盈亏/集中度/快照差异）          （本地 OCR/名称匹配/行情获取）
        │                                        │  stdin/stdout JSON-RPC 2.0（schema v1）
        ▼
Drift + sqlite3mc（SQLCipher 兼容）加密 SQLite
```

### 3.2 技术栈

| 层 | 技术 | 关键约束 |
|---|---|---|
| 界面层 | Flutter Windows、Riverpod 3、Drift、flutter_secure_storage | 不直接计算金融指标，不直接访问数据库或 Python |
| 领域层 | 纯 Dart、`decimal` 包 | 不依赖 Flutter/数据库/网络；金额一律十进制 |
| 数据引擎 | Python 3.11+、Pydantic、PaddleOCR、AKShare、BaoStock | 只做识别与数据获取，不计算总资产/收益，不写正式持仓 |
| 存储 | SQLCipher 加密 SQLite（sqlite3mc） | 密钥由 Windows 凭据管理器保护 |
| 构建交付 | PyInstaller（one-directory）、Flutter Windows release、Inno Setup 6 | 引擎随安装包内嵌，安装器按用户级安装 |

### 3.3 进程边界与协议

- Flutter 以受控子进程启动 Python 引擎，通过 **stdin/stdout 逐行 JSON-RPC 2.0** 通信，不开放本地端口。
- 协议由 `schemas/engine_protocol_v1.schema.json` 定义，消息携带 `schema_version = 1`；引擎只暴露 4 个方法：`health.check`、`ocr.parse_screenshots`、`product.match_candidates`、`market.fetch_quotes`。
- 引擎实现了 UTF-8 管道修复（应对中文 Windows 默认 GBK 管道导致的乱码）、懒启动、请求串行化、超时/取消、一次受控重启；异常退出后应用进入降级模式，继续使用缓存与手工数据。

### 3.4 数据模型

- 当前持仓（`holding`）：双轴分类（`instrument_type` 产品形态 × `asset_class` 经济资产类别），含字段来源（`field_provenance`）与估值方法。
- 历史快照（`snapshot` + `snapshot_holding`）：保存时冻结全部字段，行情刷新与后续修改不得改动；快照差额只称为“资产金额变化”。
- 其他对象：导入批次、草稿持仓、数据问题、行情缓存、分类规则、应用设置、备份元数据。
- 当前数据库 `schemaVersion = 1`，**尚无 Drift 迁移机制**（CLAUDE.md 已明确改表前需先设计迁移与升级路径）。

## 六、安全与隐私

- **数据不出本机**：持仓、截图、备份全部本地处理；唯一网络访问是免费行情源与手动触发的更新检查，且不携带持仓信息。
- **数据库加密**：sqlite3mc（SQLCipher 兼容）透明加密，密钥由 Windows Credential Manager 保护。
- **备份加密**：Argon2id 密钥派生 + AES-256-GCM 认证加密，每份备份独立随机盐与 nonce；恢复先解密到临时区域、验证校验值与结构版本、再原子替换，替换前保留可恢复副本。
- **日志脱敏**：不记录完整持仓金额、原始 OCR 文本、截图内容、密钥或备份密码；引擎 stderr 输出在进入日志前需经脱敏。
- **进程隔离**：引擎子进程只能访问应用数据目录与用户明确选择的文件；卸载默认保留 `%APPDATA%\FundLens`，删除用户数据需显式勾选。
- **仓库卫生**：`.gitignore` 覆盖数据库、密钥、截图、模型、构建产物；敏感信息扫描未发现误提交的凭据。

## 七、开发流程与工程化

- **阶段化路线图**：按四阶段推进（核心存储 → 数据引擎 → Windows UI → 备份/打包/验收），每阶段有独立验收门禁，文档齐全（`docs/superpowers/` 下含规格、计划、设计与回归记录）。
- **工作流**：Git 工作树隔离、TDD（先失败测试再最小实现）、小而清晰的提交、门禁全绿后直接合并 master、按流水线产出安装包。
- **构建流水线**：`tools/build_windows_release.ps1` 覆盖工具链验证 → 引擎打包 → 测试/analyze → release 构建 → 内嵌引擎 → bundle 校验 → Inno Setup 安装包。
- **依赖锁定**：引擎依赖有 `engine/requirements.lock` 且已提交；但两个 Dart `pubspec.lock` 被 `.gitignore` 忽略、未提交（见风险 R2）。

## 八、已知限制与产品边界

V1 有意不提供（文档明确、非缺陷）：

- 无直接持有的债券、无交易流水、无实时行情（场内用最近交易日收盘价，场外用最新净值）。
- 无云同步、无账号体系、无 Android 客户端、不自动登录平台。
- 无投资建议、无买卖/调仓/再平衡建议、无 VaR/最大回撤/波动率/夏普等量化指标、无自动交易。
- 快照差额不等于投资收益（明确文案约束）。
- 行情依赖免费公开数据源（akshare/baostock），接口可能变化或失效；失败时保留上次有效值并显示过期状态。

## 十、改进建议

优先级从高到低：

1. **建立 CI 流水线**（R1）：将 dart test / flutter test（含 sqlite3mc 包装）/ analyze / pytest / ruff / mypy 与 release 构建接入 GitHub Actions 或等价 CI，作为提交门禁，替代人工复跑。
2. **提交 Dart lockfile**（R2）：从 `.gitignore` 移除 `apps/*/pubspec.lock` 与 `packages/*/pubspec.lock`（Dart 应用/包建议提交锁文件），恢复可复现构建，并更新 CLAUDE.md 与 README 的一致性。
3. **完成发布验收闭环**（R9）：按 `tests/release/clean_vm_acceptance.ps1` 执行干净 VM 验收并更新发布报告；在 profile/release 模式复跑性能预算。
4. **拆分大控制器**（R3）：将 `import_review_controller.dart` 按导入向导步骤或职责拆分为多个 controller/service，并补充相应测试。
5. **规划数据库迁移机制**（R5）：在需要改表前先实现带版本号的迁移框架与备份升级路径，避免 v2 schema 落地时无路可走。
6. **清理脚手架残留**（R4）：完善 `fundlens_core` README、应用描述，移除样板 TODO 与占位文件。
7. **环境参数化**（R6）：将 `D:\flutter`、镜像地址、sqlite3mc 服务器端口改为可配置项（环境变量/脚本参数），并文档化生产构建的 hooks 处理。
8. **收尾工作区**（R7、R8）：提交或还原两个生成文件；删除根目录空目录 `D`。
9. **可选的体积优化**（R10）：评估 OCR 模型裁剪/压缩与 PyInstaller 依赖瘦身（低优先级，需先量化收益）。

## 十一、结论

FundLens V1 是一个**设计文档完备、架构分层清晰、测试覆盖充分、安全设计严谨**的个人资产管理桌面应用。四层边界（界面/应用/领域/引擎）与协议契约的执行质量明显高于一般个人项目，回归门禁全绿且有性能预算实测。
